\bluebigheading{PROPOSAL DESCRIPTION (10 pts)}
\vspace{5mm}
\blueheading{Motivation (1 pt)}

\begin{dynamicanswerbox}
In the modern digital information ecosystem, misinformation and sensationalized news spread rapidly across messaging platforms, social media, and digital channels. False stories, headlines and untrue claims change what people think cause fear and hurt trust, in real news. For people and students checking if a headline or article is true as it comes in is hard because of the high velocity and sheer volume of uncurated data.

Most existing verification efforts rely either on slow manual fact-checking or complex, black-box machine learning models that do not offer explainability. The core challenge is not simply assigning an arbitrary binary label of ``Fake'' or ``Real,'' but offering users a preliminary, transparent credibility score backed by diagnostic reasons explaining why a piece of news was flagged. We aim to solve this by building \textbf{VeriNews}, a fast and explainable verification engine implemented using fundamental Data Structures (DSA in C) combined with Object-Oriented Programming (C++). By extracting key entities, matching them against curated databases of verified and suspicious records, and computing an objective score across source reliability, topical alignment, and temporal consistency, our platform delivers an accessible, educational, and computational solution to help combat misinformation at the source.
\end{dynamicanswerbox}
\vspace{10mm}
\blueheading{State of the Art / Current solution (1 pt)}

\begin{dynamicanswerbox}
Today fake news verification mostly comes down to two extremes. On one side there are fact-checking portals, like Snopes, Alt News and PolitiFact. These sites rely on experts to go through claims and verify their accuracy. It's a process but it aims for precision. The other extreme is automated systems that use algorithms to detect information quickly.. These systems often struggle with context and nuance. So people end up choosing between slow and accurate or fast but not always reliable. There isn't much in the middle. and automated AI/NLP cloud APIs. Manual fact-checking provides thorough investigation but suffers from severe turnaround delays, meaning viral misinformation spreads long before a rebuttal is published. On the technological side, commercial platforms utilize complex neural networks or proprietary cloud fact-checking APIs. However, these systems function largely as opaque black boxes without revealing their internal criteria, source credibility indexes, or entity weighting to the end-user. Moreover, existing systems rarely offer standalone, lightweight rule-based software that can perform high-throughput preliminary verification locally using structured in-memory algorithms without heavy external dependencies.
\end{dynamicanswerbox}
\vspace{10mm}
\blueheading{Project Goals and Milestones (2 pts)}

\begin{dynamicanswerbox}
Our goal is to engineer a high-performance verification and credibility scoring application where users can submit headlines or article snippets and immediately receive a weighted verification score (0--100\%) along with an itemized explanation.

\vspace{1mm}
\textbf{Project Milestones:}
\begin{itemize}[leftmargin=4.5mm,itemsep=1.5pt,topsep=1.5pt,partopsep=0pt,parsep=0pt]
    \item \textbf{Milestone 1 (Phase 1):} Core Data Structure Implementation --- Build C modules for Hash Tables (keyword indexing), Linked Lists (news records), and Binary Search Trees (sorting/filtering records by score and date).
    \item \textbf{Milestone 2 (Phase 2):} Tokenization \& Verification Engine --- Develop keyword extraction, source reputation scoring, and the multi-factor weighted verification algorithm.
    \item \textbf{Milestone 3 (Phase 2/3):} C++ OOP Layer \& Request Queueing --- Build class hierarchies (\texttt{User}, \texttt{News}, \texttt{VerificationEngine}, \texttt{Admin}), FIFO request queues, and undo/history stacks.
    \item \textbf{Milestone 4 (Phase 3):} File Persistence \& Admin Module --- Implement file handling for persistent news records, trusted source registries, and administrative CRUD operations.
    \item \textbf{Milestone 5 (Phase 3):} Testing \& Comprehensive Benchmarking --- Unit test matching accuracy, edge cases, and generate final proposal deliverables.
\end{itemize}
\end{dynamicanswerbox}
\vspace{10mm}
\blueheading{Project Approach (3 pts)}

\begin{dynamicanswerbox}
We are implementing this project through a modular multi-tier architecture combining low-level C Data Structures for optimal performance with high-level C++ Object-Oriented Programming (OOP) for maintainability and modular system design:

\vspace{1mm}
\begin{itemize}[leftmargin=4.5mm,itemsep=1.5pt,topsep=1.5pt,partopsep=0pt,parsep=0pt]
    \item \textbf{Text Processing \& Keyword Extraction:} Cleans input text, strips noise, filters stop words, and tokenizes key entities.
    \item \textbf{Data Structures \& Matching Layer (C):} Hash Tables for near $O(1)$ keyword lookup, dynamic Linked Lists for record chaining, Binary Search Trees (BST) for temporal/score range filtering, FIFO Queues for input batching, and Stacks for operation history.
    \item \textbf{Multi-Factor Verification Engine:} Computes a composite weighted metric: \textit{Entity Match (40\%)}, \textit{Source Reliability (25\%)}, \textit{Corroborating Reports (20\%)}, \textit{Temporal Consistency (10\%)}, and \textit{Category Alignment (5\%)}.
    \item \textbf{Classification \& Persistence (C++ OOP):} Categorizes output into \textit{Likely Verified} (80--100\%), \textit{Needs Verification} (50--79\%), or \textit{Suspicious} (0--49\%) with structured binary/text file persistence.
\end{itemize}
\end{dynamicanswerbox}

\blueheading{Project Outcome / Deliverables (1 pt)}

\begin{dynamicanswerbox}
By the conclusion of this project, we will deliver a fully functional, self-contained C/C++ application (\textbf{VeriNews}) that enables users to evaluate news headlines and inspect detailed credibility breakdowns. Key Deliverables include:
\begin{itemize}[leftmargin=4.5mm,itemsep=1pt,topsep=1pt,partopsep=0pt,parsep=0pt]
    \item Complete, modular, and documented source code integrating custom C data structures (Hash Tables, BST, Linked Lists, Queues, Stacks) with C++ OOP classes.
    \item Pre-configured persistent dataset containing verified news, flagged suspicious records, and trusted publisher indexes.
    \item Interactive Administrative module offering full CRUD capabilities for database updates and audit history.
    \item Comprehensive project report, algorithmic complexity analysis, UML diagrams, and a live demonstration showing real-time news verification and scoring.
\end{itemize}
\end{dynamicanswerbox}
\vspace{7mm}
\blueheading{Assumptions}

\begin{dynamicanswerbox}
Submissions are assumed to be in English with sufficient entity density for tokenization. A baseline truth dataset is curated by administrators. The tool operates as a fast, deterministic local verification aid rather than an exhaustive real-time crawler.
\end{dynamicanswerbox}
